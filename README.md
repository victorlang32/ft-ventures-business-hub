## Platform Overview

FT Ventures Studio combines financial calculators, client portals, and practical business modules in a single web workspace. Teams can use it to present tools under their own branding, collect information from prospective clients, and handle recurring business processes without stitching together multiple unrelated applications.

The application is designed for static deployment, including GitHub Pages and comparable hosting services. Its capabilities cover property and finance analysis as well as customer records, invoices, accounting, appointments, galleries, inventory, and staff operations. Owner dashboards provide a broader view of information collected across these areas.

- Assemble reusable modules into branded portals for clients.

## How to Use It

A common setup and publishing sequence is:

1. Load FT Ventures Studio in a modern browser.
2. Choose or create the modules for the client portal.
3. Add branding and organize the portal layout.
4. Set up the calculators, business modules, and lead capture behavior.
5. Inspect the portal using the preview.
6. Give clients or prospects the generated portal URL.
7. Consult the owner dashboard for records and information aggregated across modules.

Typical use cases include:

- Creating a property analysis page with mortgage, cap rate, and home value calculators.
- Delivering a branded client portal that supports interaction and lead collection.
- Managing customer, invoice, booking, inventory, and staff details in one workspace.
- Retaining leads in browser storage when optional backend delivery has not been set up.

## Configuration Guide

The platform is designed to run without a build pipeline or mandatory backend. Its behavior is configured through the static application files and the settings available within the app.

Depending on how the site is deployed, check these settings and files:

- Portal identity, branding, and selected modules.
- Preview controls and links used to share portals.
- Lead collection behavior.
- Optional settings for backend delivery.
- Browser storage used to keep locally retained lead data.
- Hosting settings for the selected static-site provider.

After editing static files, publish the revised files to the hosting provider and refresh the browser before validating the changes.

## Frequently Asked Questions

### Is a backend mandatory?

No. The self-contained static deployment works without one. Leads may be stored in the browser, and an optional backend delivery route can be configured if required.

### What hosting services can I use?

FT Ventures Studio can run on GitHub Pages and other services that deliver static website files.

### Are branded client portals supported?

Yes. Reusable modules can be combined into branded portals, checked through previews, and shared using portal links.

### Which tools and modules are available?

Financial functionality includes property, mortgage, cap rate, and home value calculators. Additional modules cover CRM, invoicing, accounting, bookings, galleries, inventory, and staff operations.

### Where does browser-based lead data go?

With browser-based capture enabled, lead information is kept using browser storage. Check the selected delivery configuration to understand how a particular deployment handles that information.

### How can I publish an update?

Replace the files currently hosted with the latest build, reload the site, and confirm that the portal configuration, branding, calculators, and lead capture settings still behave as expected.

### What can I inspect when the site fails to load?

Verify that every project file was uploaded, the hosting path is correct, and the browser is displaying the newest deployment instead of a cached version. For enabled lead delivery, inspect the optional backend configuration as well.
